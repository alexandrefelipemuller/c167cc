# Memory model

The C167 has a segmented memory architecture (code segment, data page
pointers DPP0-DPP3, near/far addressing, internal RAM/SFR/ESFR areas,
external memory). This MVP intentionally implements only a small,
explicitly-scoped part of it - see [limitations.md](limitations.md) for
what is deliberately not handled yet.

## Near pointers

All pointers generated by this compiler are **near pointers**: a 16-bit
offset within the currently addressable data page. `sizeof(T*)` is 2
bytes. There is currently no support for generating far/huge pointers or
explicit segment/page switching code.

## `@ram(addr)` / `@rom(addr)`

A global declaration annotated `@ram(addr)` or `@rom(addr)` is placed at a
fixed absolute address instead of being allocated storage by an eventual
assembler/linker:

```c
@ram(0x1234)
volatile uint16_t rpm;
```

generates:

```asm
rpm             EQU     01234H          ; @ram @0x1234 (uint16_t)
```

and every read/write of `rpm` is emitted as direct addressing of that
symbol (`MOV R0, rpm`), which the assembler/linker resolves via `EQU` to
the absolute address. This assumes the address is reachable via the
active data page register (DPP) at the point of use - the compiler does
not currently emit DPP setup code. `@rom` is intended for read-only /
flash data; nothing currently prevents writing to an `@rom` symbol, so
treat this as an addressing hint rather than an enforced access class.

## Globals without an explicit address

A global with no `@ram`/`@rom` attribute is emitted into a `.bss`-style
section as a plain label with a `DS` (define storage) directive, to be
resolved by a future assembler/linker pass:

```asm
counter:        DS      2               ; uint16_t
```

## `@interrupt(n)`

Marks a function as an interrupt service routine; see
[abi.md](abi.md#interrupts) for what this currently generates.

## Stack-relative addressing

Locals and parameters live in the current function's frame and are
addressed as `[R15+#offset]` (GPR-indirect addressing with a 16-bit
offset), with `R15` acting as a compiler-managed frame pointer - see
[abi.md](abi.md).
